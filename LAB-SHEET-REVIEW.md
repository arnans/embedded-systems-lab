# Lab sheet review strategy

Use this when revising a lab sheet or comparing several versions of the same experiment. Start with the learning goal and the work students already do. Change the activity only when something essential is missing or a technical error prevents it from working.

## Review the activities side by side

1. Read the current lab sheets, including their diagrams, code, and **สิ่งที่ต้องส่ง** sections. Check the live Canvas assignment instructions and rubric. Use the rating names students see in Canvas.
2. Map each exercise to its learning goal, what students do, and the evidence they already produce. Where students use different tools, look for the same underlying idea. In Lab 1, Wokwi shows simulated signals, GoGo CM teaches students to trace an assembled board’s schematic, and the breadboard version lets them build and probe a circuit.
3. For a review, show one column per lab and one row per exercise. Mark what is **There**, what you would **Add**, **Remove**, or **Modify**, and what you would **Keep**. Make the workload impact clear. Reuse existing observations, captures, or explanations before proposing more work. If two items prove the same thing, keep the one that shows the learning goal most directly.
4. Trace technical claims back to the schematic, pinout, code, or official documentation. Check that diagrams and instructions describe the same wiring. If a circuit changes, check any exercise in another sheet that uses its values or results. Say whether a result was calculated, simulated, or measured on the bench.

## Make the report checklist match Canvas

- Put one **สิ่งที่ต้องส่ง** checklist near the end. Use the same exercise numbers as the activity and keep each item short. Let students reuse evidence across exercises when one image or capture shows both results.
- Name the evidence and say what it should show. Where Canvas expects an explanation, say so explicitly. For example, in Hello World, ask for the Serial Monitor screenshot and which part of the code makes the message appear every second.
- Explain the top rating in one short line using the live rubric. For Lab 1, **ดีเยี่ยม** means clear, complete evidence and a reasoned explanation for each exercise. Tie the explanation to the relevant code, circuit, or signal.
- Let the evidence fit the platform. For example, in Lab 1A’s counter exercise, the existing Serial Monitor output shows whether a held press counts once. That replaced a required extra LED blink pattern and its PulseView capture.

## Edit the Thai and verify the result

- Write as an instructor speaking to students. Put the action first, then say what to look for or explain. Use complete, connected sentences in the instructions and short phrases in the checklist.
- Use natural Thai for explanations, such as “แผนผังวงจร” and “พอร์ต”. Keep menu labels, component names, commands, and signal values as students see them, such as `USB CDC On Boot`, `GPIO4`, and `HIGH`.
- After editing, compare the checklist with the activity and Canvas rubric. Follow links in the table of contents, check diagrams and cross-references, and review the diff for any added work. When a sheet has an AI declaration, keep it accurate about the tools used and their role. After publishing, reopen the GitHub version to verify the result.
